## 1. О продукте

**Admitica** — веб-приложение (SPA) для русскоязычных абитуриентов, поступающих в **европейские университеты**:
- находить и сравнивать **вузы, гранты/стипендии, стажировки**;
- сохранять программы, расставлять приоритеты, строить **roadmap** поступления;
- **AI-фидбэк по эссе**; сборка **резюме (CV) через AI-чат**; экспорт в **DOCX/PDF**.

Интерфейс — **русский** (мультиязычность UI в планах; сейчас на язык пользователя переключаются только ответы ИИ).

**Команда:** основатель + кофаундер (+ возможно ещё 1). Кофаундер настаивает на **Claude Opus** как основной модели.

## 6. Контент-слой: каталог через Google-таблицу (СПРОЕКТИРОВАНО, не реализовано)

**Проблема:** данные захардкожены в `data/programs.js` → добавить вуз нельзя без кода. **Решение:** вынести контент в **Google-таблицу**, сайт читает её при загрузке (кэш в localStorage + fallback на встроенные данные). Десктоп и мобайл — один источник.

### Структура (3 вкладки)
- **INBOX** — `type | name | source_url | status(new/processing/done/error) | added_by | added_at`. Сюда вставляют ссылки (поодиночке или **пачкой**).
- **REVIEW** — поля программы + провенанс (цитаты-пруфы, `ai_confidence`, `flags`) + `reviewer | status(draft/approved/rejected) | review_notes | last_verified`.
- Сайт читает **только `status = approved`**.

### Ключевые решения по данным
- **`id` — ручной короткий слаг** (`bocconi-msc-econ`), задаётся раз и **не переиспользуется** (на него ссылаются `savedIds`/`priorities`/`roadmaps`).
- **Дедлайн — ДАТА** (`2026-09-01`); `deadlineDays` **вычисляется кодом** (старое поле-число протухало).
- **Авто-выводимые** (не заполнять руками): `flag` (из country), `initial` (из name), `color` (из палитры по id), `deadlineDays`.
- **Дропдауны** в таблице для `country/degree/field/language/format` — чтобы фильтры «Найти» не ломались от опечаток.

## 7. Пайплайн парсинга и верификации (СПРОЕКТИРОВАНО, не реализовано)

**Цель:** парсить с **официальных** страниц → проверять **сначала ИИ, потом человеком (для сложного)** → на сайт.

```
INBOX (Sheet) → триггер → Cloudflare Worker
  → чистка страницы: Jina Reader / Firecrawl (JS-сайты, PDF)
  → ИЗВЛЕЧЕНИЕ: модель → JSON + ДОСЛОВНАЯ ЦИТАТА-пруф + confidence на КАЖДОЕ поле
  → ВЕРИФИКАЦИЯ: Opus-критик + правила (валидность дат/диапазонов)
REVIEW (Sheet → потом админ-панель) → человек одобряет только спорное
Каталог (approved) → сайт
  ↑ Cron: перепроверка свежести, диффы → назад в REVIEW
```

### Ядро — grounded extraction (защита от галлюцинаций)
ИИ на каждое поле: **значение + дословная цитата с источника + confidence**; нет поля → `null`, не выдумка.
- **Авто-одобрение:** есть цитата + проходит проверку типа/диапазона + высокий confidence.
- **К человеку:** нет цитаты / низкий confidence / провал проверки / субъективное поле / противоречия.
- Запись публикуется авто только если **все критичные поля** прошли.

### Поля «ВСЕГДА человек» (зафиксировано)
**Дедлайн, стоимость, языковые требования (IELTS и т.п.)** — минимум на старте.

### Решения по масштабу
- **Объём:** сотни записей. **Узкое место — человеческое ревью** (3 ревьюера: основатель + кофаундер + 1).
- **Фазы:** Фаза 1 — на Google-таблице, отладка качества на **~50** записях (без админки). Фаза 2 — **админ-панель** в Vite (за паролем): очередь, источник и значение бок о бок, разделение между ревьюерами. Worker/извлечение — общие.
- **Снижение нагрузки:** группировать однотипные источники; trust-tiering (по статистике); приоритизировать востребованное; делить очередь по `reviewer`.
- **Модели:** извлечение — дешёвой моделью; **верификация — Opus**.
- **Провенанс обязателен:** `source_url`, `fetched_at`, сырой JSON, цитаты, кто/когда одобрил.
