# Спека: витрина «Китай» (ветка `china`)

**Что строим.** Бесплатная публичная витрина по поступлению в Китай на существующем Vite-аппе (`app/`): каталог из ~20 вузов с проверенными карточками, фильтр формального соответствия, «мой план» (дедлайны, документы, статусы) в браузере, лид-путь к партнёру-консультанту. Данные приходят **только** из `app/public/data/china.json`, который делает конвейер (репозиторий `Abitura pipeline`, задача 26).

**Чего нет и не будет в этой ветке:** ИИ-фичи (эссе, резюме, Uni-fit, ассистент) — спрятаны за флагом; оценка шансов и ярусы «Мечта/Цель/Надёжный» — **никогда** (это товар консультанта); аккаунты и бэкенд — фаза 2; файлы пользователя — никогда.

**Инварианты:**
- Витрина **не форматирует значения**: печатает `display` из JSON. Ни одного `toLocaleString`/своего форматтера денег и дат для фактов.
- **Ни одного факта без источника и даты в UI.** Если у факта нет `source_url`/`verified_at` — он не рендерится (и это баг экспорта, не витрины).
- Существующие ключи `admitica.*` **не трогаем** (данные текущих пользователей). Всё новое — под префиксом `admitica.cn.*`.
- Дизайн — `DESIGN.md` как есть. Никаких новых токенов, шрифтов, редизайна. Тёмная тема по умолчанию, светлая через `[data-theme="light"]`.
- Бренд, тексты, ссылки партнёра — **конфигом**, не хардкодом (`app/src/lib/partner.ts`).
- Никакой ИИ-ключ, никакой внешний вызов из витрины. Единственные внешние ссылки — официальные страницы вузов и Телеграм партнёра.

## 1. Слой данных (`app/src/data/china.ts`, `app/src/data/china.types.ts`)

- Типы 1:1 к структуре экспорта (см. задачу 26 §5): `Catalog`, `University`, `Fact`, `FactKey` (строковый union из 8 ключей карточки).
- `loadCatalog(): Promise<Catalog>` — `fetch('data/china.json')` с относительным путём (base `./`), кэш в памяти. Если файла нет — встроенный фикстурный каталог `china.fixture.ts` с `demo: true`, и UI показывает баннер «демо-данные, не прошли конвейер». Фикстура — только реальные значения с официальных страниц (из ресерча 31.08: Tsinghua tuition 26 000–40 000 ¥, HSK 5, раунды 30.09–28.11.2025 / 29.11.2025–28.02.2026; ZJU 19 800–42 800 ¥, подача 01.12.2025–28.02.2026, CSCA требуется с 2026/27; SJTU англ. бакалавриат 120 000 ¥, дедлайн 31.03.2026; XJTLU 93 000 ¥, IELTS 5.0/6.5), с `origin: "demo"` и `source_url` реальной страницы. Выдуманных чисел в фикстуре быть не может.
- Хелперы: `factsOf(u, key)`, `criticalKeys` (дедлайны, HSK, CSCA), `lastChecked(u)`.

## 2. Партнёр (`app/src/lib/partner.ts`)

```ts
export type Partner = { slug: string; name: string; tagline?: string; logo?: string;
  lead: { label: string; url: string }; expertPage?: {...}; universities?: string[] }
```
- `partners.ts`: `abitura` (дефолт, без лида) и `zhuiqiu` (демо: имя, ссылка на ТГ — см. ответ владельца, кейсы). Выбор: `?partner=zhuiqiu` или `VITE_PARTNER` при сборке; **публичная сборка по умолчанию — `abitura`**. Бренд партнёра не показывается никому, кроме как в демо, пока он не согласился.
- Всё, что зависит от партнёра: шапка (имя/логотип), лид-кнопки, страница эксперта, текст в попапе.

## 3. Экраны

### 3.1 Home — лендинг (`pages/Home.tsx`, переписать содержимое)
Заголовок про Китай, три обещания (каждая цифра с источником и датой; CSCA — что требует именно этот вуз; бесплатно), CTA «Подобрать вуз» → онбординг/каталог, блок «как читать бейджи», честный абзац про CSCA (с 2026/27 обязателен для вузов сети правительственных стипендий и для стипендии CSC; для всех вузов и минимальные баллы — план с 2028; вузы применяют по-разному). Без стоковых картинок.

### 3.2 Каталог (`pages/Find.tsx`, переделать)
- Карточки вузов (`ProgramCard` → адаптировать в `UniversityCard`): название, город, 3 ключевых факта (`display`), бейдж CSCA (требуется / не требуется / «не опубликовано»), покрытие «7 из 8 фактов проверено», дата последней проверки.
- Фильтры: город, язык обучения, требуется ли CSCA, HSK ≤ мой, бюджет/год ≤ мой (по `fees.tuition_year_non_eu`), есть стипендия с покрытием обучения, дедлайн ещё не прошёл. Сортировка: дедлайн ближайший / стоимость.
- **Соответствие профилю** (`lib/match.ts`, чистая функция с тестами): по профилю из онбординга — для каждого вуза список `ok[]` и `gaps[]` («не хватает HSK 4», «дедлайн прошёл», «дороже бюджета»). Только формальные условия по опубликованным фактам; нет факта → «не проверено», не «нет». **Никаких вероятностей, ярусов, «шансов».**

### 3.3 Карточка вуза (`pages/Detail.tsx`, переписать под JSON)
- Шесть строк карточки в порядке: дедлайн · стоимость/год · язык + HSK/IELTS · CSCA · стипендия · общежитие/мес. Каждая строка — `FactRow`: `display`, учебный год, **`ProvenanceBadge`**.
- `ProvenanceBadge` (`components/ProvenanceBadge.tsx`): три состояния —
  «проверено автоматически · <дата>» (`origin=auto`, snapshot fetch/browser) · «проверено вручную · <дата> » (`origin=manual`) · «по архивной копии от <дата>» (`snapshot.render_method=wayback`, показать `archived_at`). Клик → раскрывает дословную цитату и ссылку на официальную страницу. Демо-факты (`origin=demo`) — четвёртый, откровенно серый бейдж «демо».
- Пустой факт — строка «вуз не публикует · проверено <last_checked_at>», не пропуск строки.
- Блок CSCA: статус, модули, честная сноска про поэтапное введение; если `csca_required` отсутствует — «вуз не заявил, проверено <дата>».
- Строка «год в Китае ≈ обучение + 12 × общежитие» — считается из `value.amount_minor` только для отображения суммы **и печатается с пометкой «оценка»**; это единственное вычисленное число на странице.
- Кнопки: «В мой план», «Обсудить с <партнёр>» (только если у партнёра есть `lead`).
- Критичные поля — отдельная строка под карточкой: «сверьтесь с сайтом вуза перед подачей» (та же, что в Пульте).
- Bocconi-контент (`data/bocconi.ts`, `uniContent.ts`), Uni-fit, AdvicePanel — не удалять, отключить импортом за флагом.

### 3.4 Мой план (`pages/Plan.tsx`, новый; вместо `Programs.tsx` в навигации)
Хранилище `admitica.cn.plan` (JSON): `{ universities: [{ id, status: 'considering'|'preparing'|'applied'|'answered', docs: Record<string, boolean> }] }`.
- **Лента дедлайнов**: все дедлайны выбранных вузов + фиксированные общие даты (сессии CSCA 2026: янв/март/апр/июнь/дек; окно CSC ~дек–апр) в одном списке по возрастанию с обратным отсчётом. Общие даты помечены «общие, по csca.cn/CSC», с датой проверки текста.
- **Документы** по вузу: базовый список (паспорт, аттестат/транскрипт + нотариальный перевод, HSK/IELTS сертификат, CSCA score report — если требуется, мотивационное письмо, рекомендации, медсправка, фото) + `docs.required_list` из JSON, если есть. Чекбоксы.
- **Статусы** по вузу.
- «Поделиться с наставником» — формирует текстовый свод (вузы, статусы, ближайшие дедлайны, готовность документов в %) и открывает `https://t.me/share/url?text=…` или копирует. **Экспорт/импорт JSON** файла плана (страховка от потери localStorage).

### 3.5 Онбординг (`pages/Onboarding.tsx`, урезать)

## 5. Тесты и приёмка
- `lib/match.ts` и `lib/plan.ts` (лента дедлайнов, свод) — vitest, чистые функции.
- `npm run build --prefix app` зелёный, `npm run lint` зелёный.
- Ручная приёмка: с чистым localStorage пройти онбординг → каталог → карточка → в план → лента → поделиться; на мобильной ширине (375) ничего не выпадает; в светлой теме бейджи читаемы.
- Скриншоты трёх экранов (каталог, карточка, план) — сложить в `docs/screens/` для утреннего просмотра.
