## 1. Что это за продукт

**Admitica** — веб-приложение (SPA) для русскоязычных абитуриентов, поступающих в **европейские университеты**. Помогает:
- находить и сравнивать университеты, гранты/стипендии, стажировки;
- сохранять программы, расставлять приоритеты, строить «дорожные карты» (roadmap) поступления;
- писать мотивационные эссе с AI-фидбэком;
- собирать резюме (CV) через AI-чат;
- скачивать эссе и резюме в DOCX/PDF.

Язык интерфейса — **русский** (планируется мультиязычность). Целевая аудитория — русскоязычные студенты, поступающие в Европу.

**Команда:** основатель (пользователь, с которым работает Claude) + кофаундер. Кофаундер настаивает на использовании Claude **Opus** как основной AI-модели.

**Стадия:** ранний прототип / демо. Задеплоено на GitHub Pages.

## 2. Технологический стек

| Слой | Технология |
|------|-----------|
| Фреймворк | **React 18.3.1** через CDN (UMD-сборка) |
| JSX-транспиляция | **Babel Standalone 7.29** — компиляция в браузере на лету (НЕТ сборщика!) |
| Стили | Чистый **CSS** с CSS-переменными (`styles.css`) |
| Хранение данных | **localStorage** (префикс `admitica.`) |
| Хостинг | **GitHub Pages** (статика, без бэкенда) |
| AI | **OpenRouter API** (сейчас), есть поддержка Gemini |
| Экспорт документов | `docx` (DOCX) + `pdfmake` (PDF) — обе через CDN, генерация в браузере |

**Ключевая особенность:** проект **полностью статический** — нет сборки (no webpack/vite), нет бэкенда, нет Node-сервера. Просто HTML + JSX, которые Babel компилирует прямо в браузере. Это накладывает ограничения (см. раздел про AI и безопасность ключей).

## 4. Определение устройства и роутинг десктоп/мобайл

В `<head>` обоих HTML — inline-скрипт:
- Определяет мобильное устройство по `navigator.userAgent` + размер экрана + touch.
- iPhone/Android → редирект на `mobile.html`. ПК → `index.html`. iPad/планшеты → десктоп.
- Ручное переопределение через `?view=desktop` / `?view=mobile` (сохраняется в `sessionStorage.admitica.view`).
- На реальном тач-устройстве мобильная «рамка телефона» (mockup) убирается через media-query → fullscreen.

## 6. Функционал (текущий)

### Общий (десктоп + мобайл)
- **Онбординг:** ввод имени, текст «Поступление в ВУЗ мечты — твой путь.»
- **Главная:** приветствие по времени суток, цитата дня, **GoalTracker** (прогресс по roadmap в %), приоритеты, ближайшие дедлайны. (Десктоп доп: стрик-календарь.)
- **Найти:** поиск + фильтры (страна, направление, уровень, стоимость, формат), сегменты Вузы/Гранты/Стажировки.
- **Мои программы:** сегменты Сохранённые / Приоритеты / **Roadmap**.
  - Приоритеты в мобайле — **drag-and-drop переупорядочивание** (pointer events).
  - Roadmap — 4 шага: Изучить → Документы → Подать → Дождаться ответа.
- **Detail:** полная карточка, save/priority/+roadmap, кнопка «Спросить AI о программе».
- **Эссе:** 3 преднастроенных задания (Bocconi PS / LSE SoP / HEC Motivation). Bocconi — с готовым образцом. AI-фидбэк (3 замечания). Экспорт DOCX/PDF.
- **Резюме:** AI-чат (2 уточняющих вопроса → готовый пункт CV в JSON) + ручное добавление достижений. Экспорт DOCX/PDF.
- **Профиль/Настройки:** имя, 3 тарифа (Free / Pro / Premium), статистика, переключение десктоп/мобайл, сброс данных.

### Отличия
- **Удалено по запросу:** Pomodoro-таймер, тренажёр словаря (Vocab) — были раньше, убраны.
- Мобайл: нижняя таб-панель (Главная/Найти/Мои/Профиль) вместо сайдбара.
- Иконки-аватары программ заменены на **флаги стран** (rounded rectangle) в мобайле.

### Хранение (localStorage, префикс `admitica.`)
`name, plan, savedIds, priorities, roadmaps, essayDrafts, achievements, chat_v2, gemini_key, ai_model_*, view`

## 7. AI-интеграция (`src/ai.js`) — ТЕКУЩЕЕ СОСТОЯНИЕ

**Мульти-провайдер, определение по префиксу ключа:**
- `sk-or-*` → **OpenRouter** (OpenAI-совместимый chat completions API)
- `AIzaSy*` / `AQ.*` / `ya29.*` → **Google Gemini**

**Текущая рабочая конфигурация:**
- Провайдер: **OpenRouter**
- Модель по умолчанию: `openrouter/owl-alpha` (единственная free-модель, что заработала; экспериментальная)
- Ключ: **захардкожен** в `ai.js` как `FALLBACK_KEY` (разбит на куски массивом `.join('')`, чтобы обойти GitHub Secret Scanner). ⚠️ Виден в исходниках сайта.
- Локально перебивается через `config.js` (`window.GEMINI_KEY`), который gitignored.

**Публичный API:** `window.ai.complete(prompt, opts)`, `window.ai.extractJson(text)`, `window.ai.detectLang()`, `getProvider/getModel/setModel`. Бэк-compat шим `window.claude.complete` (десктоп-код исторически его использует).

**Определение языка:** `detectLang()` читает `navigator.language` → код языка → в системный промпт добавляется инструкция отвечать на языке пользователя (~20 языков). JSON-safe (ключи остаются английскими).
**ВАЖНОЕ ОГРАНИЧЕНИЕ:** язык переключает только **ответы ИИ**, сам **интерфейс остаётся русским** (i18n UI ещё не сделан — в планах).

**Где используется AI:**
- Эссе: запрос 3 замечаний (JSON-массив `{type, txt}`).
- Резюме: 2-ходовой чат (уточнение → JSON-пункт `{title, org, desc, skills}`).
- Detail: краткий разбор программы (свободный текст).

### История борьбы с провайдерами (контекст)
- Groq — не открывается из РФ.
- Gemini — пробовали; пользователю выдаются ТОЛЬКО ключи формата `AQ.*` (Express Mode), которые **истекают** и имеют квоту ~0/жёсткие лимиты. Классические `AIzaSy*` через Google Cloud Console получить не удалось (API не активируется в проекте).
- OpenRouter — работает из РФ; но free-модели сильно урезаны (~20-50 запросов/день, многие отдают 404). Сейчас работает только `openrouter/owl-alpha`.
- Принимают RU-карты через Stripe (для пополнения баланса).

## 9. Безопасность (текущие проблемы)
- **AI-ключ виден в публичном коде** (обфускация массивом обходит только авто-сканер GitHub, не людей).
- Mitigations: рекомендован spending cap на OpenRouter, отдельный ключ под публичный сайт.
- GitHub Push Protection дважды блокировал коммиты с ключами (Gemini, OpenRouter) — решалось обфускацией.
- **Правильное решение (в планах):** backend-прокси (Cloudflare Worker), который прячет ключ.

## 10. ЧТО ОБСУЖДАЛОСЬ ТЕОРЕТИЧЕСКИ (для второго чата — это ключевое)

Пользователь хочет **повысить качество AI-ответов по эссе/заявкам**, опираясь на базу эталонных эссе. Обсудили:

### Варианты «обучения» на датасете эссе
1. **Few-shot** (примеры в промпте) — 3-5 эталонов в системный промпт. Быстро, бесплатно, но мало примеров влезает.
2. **Fine-tuning** — дообучение open-weights модели (Qwen 2.5 7B / Llama 3.1 8B) на 300-1000+ примерах. Меняет стиль/поведение, НЕ факты. Нужен датасет (сбор — основная работа). Делается на Together AI / Fireworks / своём GPU. ~$30-50 и ~неделя. OpenRouter fine-tune НЕ делает (только инференс).
3. **RAG (эмбеддинги + векторный поиск)** — для опоры на БОЛЬШУЮ базу (300-500 эссе). Эмбеддишь все эссе → при запросе достаёшь топ-K релевантных → кладёшь в промпт.

### Ключевые выводы из обсуждения
- **Fine-tuning учит СТИЛЮ, RAG даёт ФАКТЫ/конкретные примеры.** Для «ориентироваться на 500 эссе» — это RAG (или fine-tuning, если цель — впитать общий стиль).
- **Нельзя дообучить любую модель.** Open-weights (Llama, Qwen, Mistral, Gemma) — да. Проприетарные (GPT-4, Claude, Gemini) — нет (веса закрыты), только через API вендора если он разрешает.
- **Claude Opus дообучить НЕЛЬЗЯ.** Anthropic не даёт fine-tuning для Opus.

### Кофаундер настаивает на Opus 4.8 → принятая стратегия
Раз Opus нельзя дообучить, единственный путь опереться на большую базу эссе — **RAG**:
- Преимущество Opus: огромное окно контекста (~200K токенов) → влезает **20-40 эталонов** на запрос (против 3-5 у мелких моделей).
- Архитектура «два уровня»: **канон** (5-10 лучших эссе, всегда в промпте, закэшированы) + **динамика** (топ-15-20 под конкретный запрос через RAG).
- **Prompt caching** обязателен (Opus дорогой ~$15/млн вход) — кэш статичной части даёт скидку ~90%.
- Стек: эмбеддинги (Voyage AI / OpenAI / BGE) + векторная база (Qdrant / Pinecone / Supabase pgvector) + Cloudflare Worker + Anthropic API.
- Цена: ~$0.05-0.15/запрос (с кэшем меньше), ~$15-40/мес на 1000 запросов с кэшем. Это про качество, не экономию.
- При масштабе → **дистилляция**: Opus генерит золотой датасет → дообучаешь дешёвую Qwen 7B → переключаешь инференс на неё.

### Про серверы (вывод)
- **GPU-сервер под ИИ не нужен НИКОГДА** при использовании API — вычисления у провайдера.
- **Лёгкий serverless-бэкенд** (Cloudflare Worker / Vercel function) нужен для продакшна: спрятать ключ + RAG-поиск. Это не «тяжёлый сервер».
- Свой GPU — только при self-hosting модели (приватность данных). Для Admitica избыточно.
